# 资金费偏斜动量策略(Freqtrade 实现,已实测)

信号来源:冷门永续合约的资金费率结算出现极值时,**站在付费的一方**——拥挤的仓位继续被推着走。
本文档与其他三份不同:这里的每个数字都是在本地 perp 数据上实测出来的,不是设计意图。
回测纪律见主 SKILL.md §2;本文档在 §6 给出**四条**实测补充,违反其中任何一条会得到反号的结论。

**当前生产配置是 `FundingSkewMomentum5m` + `config-funding-skew-dryrun.json`,见 §10 运行手册。**
§4 与 §5.6 是 1m 窄宇宙口径的历史记录,数字偏高(资金费未计入,原因见 §6.4),
唯一可用于设定预期的数字在 §5.8。

**定位**:这是 `event-driven.md` §1「资金费率极值」的实测分支。那份文档把这类交易描述为
「收 funding 的 carry」与「挤压方向的价格移动」两种;实测结果是前者亏钱,后者赚钱,
且方向与直觉相反——赚钱的是**付**资金费的一侧。

## 0. 先看否决记录(省掉重复劳动)

同一份数据、同一套成本假设下,本 skill 另外三条策略线的实测结果。**不要在没有新证据的情况下重做**:

| 策略线 | 实测结果 | 判定依据 |
|---|---|---|
| `leadlag-follower.md` | BTC→冷门 pair 的 1m 滞后相关:lag1 中位数 0.0096、最大 0.046(lag0 为 0.38) | 低于该文档 §0 自己的 30 秒滞后门槛 |
| `overshoot-reversion.md` | maker 挂单 + 8bp 穿价折价后,训练段毛收益 **-2 ~ -5bps**,仅 holdout 段 +9~11bps | 主 SKILL.md §2.3,训练段为负 |
| 资金费 carry(跨结算收费) | \|fr\|≥40bps 时收 funding +55bps、价格腿 -76bps,**净 -21bps**;全部分桶、全部窗口一致为负 | 同上 |

carry 这一条的失败方式有信息量:**收费方在价格上亏掉的比收到的多**。这直接指出了赚钱的那一侧。

## 1. 宇宙定义与数据准备

- 宇宙:Binance USDT 永续,**前 30 天日成交额中位数 ≥ 1000 万美元,不设上限**。
  该门槛在入场时点用过去数据实时判定(`min_qv` 参数),不是静态白名单。
  全宇宙 806 个 pair 中,19.5 个月内有 190 个至少触发过一次合格事件。
- **本 skill 名字里的「冷门」在这条策略上是错的**。最初按 300 万 ~ 6000 万的「冷门带」筛,
  在 2025 上半年是亏的;详见 §5.5。带上限没有任何好处,下限抬到 1000 万才是关键。
- **资金费结算周期不是统一的 8h**。实测该宇宙内:4h 共 115 个 pair、8h 共 53 个、
  含 1h 的 59 个。Freqtrade 在 Binance 上按 `funding_fee_timeframe = 8h` 记账。
- 因此重建数据目录时,把桶内费率**求和**成 8h 一档,保证一段持仓的总融资成本不失真;
  同时把持仓上限压到 240 分钟以下(见 §3),让任何结算点都落不进持仓区间,
  记账口径的偏差自然归零。
- 数据可用范围:1m K 线与资金费均从 **2025-01-01** 起,806 个 USDT 永续。

```
scripts/build_niche_funding_datadir.py   # K 线软链 + funding_rate/mark 按 8h 重建
scripts/build_niche_dailyvol.py          # 前 30 天日成交额中位数(已右移一天)
user_data/data/niche_funding/futures/    # 产出:回测用独立 datadir
```

## 2. 信号

在结算时刻 T,已结算费率 `fr` 已知(T 时刻这根 1m K 线尚未收盘,不构成前视)。

```python
side  = sign(fr)                    # fr > 0 → 做多;fr < 0 → 做空(即支付资金费的一方)
入场  = T+1 分钟这根 K 线的开盘价    # Freqtrade 在 T 这根上出信号,下根开盘成交
条件  = abs(fr) >= 40bps  且  上一次结算也极端且同向
```

事件研究(算术收益,已扣 20bps 双边成本,无组合约束):

| 窗口 | n | 均值 | 中位 | 胜率 |
|---|---|---|---|---|
| 2025-11 ~ 2026-05 | 2207 | +136bps | +130bps | 60.9% |
| 2026-06 ~ 2026-08 | 620 | +368bps | +205bps | 63.4% |

10 个自然月全部为正;剔除贡献最大的 5 个 pair 后仍 +194bps;剔除最好的 3 笔仍 +264bps。
**97.6% 的样本是空头**——极端负资金费的小市值 perp 处在持续下跌中,拥挤的空头仓位在付费,
而价格继续往它们的方向走。多头样本在整个区间只有 25 笔(见 §5)。

### 2.1 连续性:edge 不在首次出现时

按「该轮连续极端结算的第几次」拆分(净 bps):

| streak 位置 | train | holdout |
|---|---|---|
| 0(该轮首次) | **-7.7** | +166.4 |
| 1 | +81.9 | +54.6 |
| 2 | +90.3 | +245.1 |
| ≥3 | +113.7 | +284.6 |

交易的是**已经被套住的拥挤仓位**,不是刚形成的。要求上一次结算也极端同向(`streak >= 1`)
是入场条件的一部分,不是可调参数。注意这条规则是看过 train 段之后选的。

## 3. Freqtrade 实现要点

策略 `user_data/strategies/FundingSkewMomentum1m.py`,配置 `config-funding-skew.json`。

```python
timeframe = "1m"
can_short = True
minimal_roi = {"0": 100}
stoploss = -0.99                    # 引擎止损退到逐仓爆仓线,不参与决策
order_types = {"entry": "market", "exit": "market", "stoploss": "market"}

fr_threshold = 40.0                 # bps
min_streak   = 1
close_stop   = 0.15                 # 按观察价止损,在 custom_exit 内判定
hold_minutes = 235
allow_long   = False
min_qv       = 1e7                  # 入场时点的前 30 天日成交额中位数下限(USDT)
max_qv       = 1e12                 # 上限;默认相当于不设,只为复现带状宇宙时用
```

三个设计点,每一个都是踩过坑之后定的:

1. **持仓 235 分钟而非 240**。4h 与 8h 两种结算周期下都不会有结算点落在持仓区间内。
   结算只作为信号,不作为收益来源——收 funding 的那条路已经在 §0 被否掉了。
2. **止损不走引擎 `stoploss`**,在 `custom_exit` 里按观察价判定,详见 §6.1。
3. **入场、出场都用市价单**。先验证 taker 版本能不能活;能活再考虑 maker。
   当前所有成交假设都比 maker 版保守。

当前推荐配置的结果在 §5.6。** 保留本节是因为它是 §6 各条纪律的取数来源。

fee 0.001/边(5bp taker + 5bp 半价差注入),stake 150,钱包 1000,`max_open_trades = 6`,
127 个 pair(全期至少出现过一次极端结算的;无事件的 pair 一笔不开,P&L 完全相同)。

|---|---|---|

## 5. Walk-forward、多头开关、宇宙与时间范围

7 个月度 fold(2026-02 ~ 2026-08),每个 fold 一次独立 Freqtrade 回测,并发跑。

```
scripts/niche_funding_walkforward.py   # 离线选参(路径模拟器,含组合约束)
scripts/niche_funding_wf_runs.py       # 按 fold 生成参数固化的策略子类
user_data/niche_work/run_wf.sh         # 分批并发启动器
```

### 5.1 逐 fold 结果(固定默认参数,仅空头)

累计 **+141.94%**,6/7 个 fold 为正,649 笔,最差 fold 回撤 13.6%。
单月区间 -0.42% ~ +35.83%。

### 5.2 选参反而更差

每个 fold 用前 3 个月在 72 格网格上选参,测下一个月:

| 选择方式 | 累计(离线,单份 stake) | 为正 fold |
|---|---|---|
| 按总收益选 | +721.6% | 6/7 |
| 按单笔均值选 | +74.8% | 4/7 |
| **固定参数** | **+969.2%** | 6/7 |
| 事后最优(上限) | +1900.1% | 7/7 |

**这个策略不要 hyperopt**。fold 样本太小,按总收益选会一路选到最松的门槛(买交易笔数),
按均值选会选到样本个位数的配置。主 SKILL.md §2.3 的「禁止大网格搜索」在这里是实测结论。

### 5.3 多头开关

在部署阈值下**基本是个空开关**:7 个 fold 共触发 8 笔多头(全在 2026-06),亏 16.3 USDT。
fr≥40 + streak≥1 门槛下几乎不存在正向极端资金费。

为了让多头真正触发,另跑一组放松门槛的诊断臂(fr≥30、streak=0、其余不变):

| | 仅空头 | 多空双向 |
|---|---|---|
| 累计 | +199.47% | +206.55% |
| 为正 fold | 6/7 | 6/7 |
| 最差 fold 回撤 | 28.3% | 29.8% |
| 多头笔数 / P&L | — | 50 笔 / +69.3 USDT |

50 笔、4/7 个 fold 为正、单 fold 从 -65.5 到 +50.8 USDT。**两个方向都不构成证据。**
`allow_long = False` 的理由是「没有证据支持」,不是「多头有害」;开着也没赚到能说话的钱。

### 5.4 一个曾经未结的悬案

(2026-08-30 已被 §5.5 的扩展测试取代:那个放松门槛的配置之所以看起来更好,
是因为它顺带放宽了流动性构成。真正起作用的是流动性下限,不是资金费门槛。原文保留如下。)

5.3 那个放松门槛的固定配置在这 7 个 fold 上分数更高(+199.5% vs +141.9%,
离线 +1292% vs +969%),但最差 fold 回撤也差很多(29.8% vs 15.4%)。

**这个比较不干净**:它是看完这批 fold 之后才注意到的,属于同一批数据上的事后选择。
而 §2.1 的 streak 单调性是在 2025-11 ~ 2026-05 上量的,在 2026-02 ~ 08 这批 fold 里没兑现。
要换配置必须往前再测一段,不能拿这个数字下结论。

全期 19.5 个月合并口径(与 §7 之前那个 -189 USDT 可比):

| 宇宙 | pair | 总额 | 剔 top3 pair | 剔 top5 | 剔 top10 |

### 5.9 持仓时长与结算周期的交互(已测,结论是不要缩短)

币安在挤压最剧烈时把 pair 切到 **1h 结算**——那正是本策略最强的信号。225 分钟持仓会跨过
3 次小时结算,按触发入场的那个极端费率付钱。缩短持仓避费的想法是错的:

| 1h 结算 pair (n=1333) | 净单笔 | 其中资金费 |
|---|---|---|
| 50m(付 0 次) | -16.8bps | +0.0 |
| 110m(付 1 次) | +20.1bps | -77.6 |
| 170m(付 2 次) | +41.8bps | -143.5 |
| 225m(付 3 次) | **+76.6bps** | -201.2 |

资金费涨得快,价格移动涨得更快。付 168bps 抓约 500bps。**不要因为付费就排除 1h 结算的 pair,
它们是赚钱的那批**:2026Q2 里付费的 74 笔净赚 +336bps/笔,未付费的 58 笔是 -25bps/笔。

反向的发现(尚未采纳):对 4h/8h 结算的 pair,225 分钟偏短。

| 4h/8h pair (n=1095) | 净单笔 | 资金费 | 为正季度 |
|---|---|---|---|
| 225m | +6.7bps | -1.6 | 3/7 |
| 340m | +38.0bps | -56.9 | 6/7 |
| 470m | +52.5bps | -58.8 | 6/7 |
| 700m | +80.2bps | -105.6 | 6/7 |

当前配置下 4h/8h 那一半几乎不赚钱,整体收益基本靠 1h 结算的 pair 扛。延长持仓、主动付资金费
更好,和最早事件研究里 480m > 240m 的结论一致(当时为避开结算点砍到 235)。
但这是在同一批数据上比出来的,**改持仓是需要独立验证的大改动,dry-run 期间不要动**。
列为下一轮测试的头号候选。

## 6. 实测补充的回测纪律(在主 SKILL.md §2 之上)

### 6.1 冷门 pair 的 1m 止损必须按观察价,不能按盘中最高/最低价

Freqtrade 的引擎 `stoploss` 按 K 线的 low/high 判定。在这些薄币上,1m 插针会扫掉止损,
**而这些单子放到持仓期满平均是赚的**。

实测(2025-11 单月,-25% 引擎止损):

```
hold_elapsed  271 笔  +200.6 bps/笔
stop_loss      27 笔 -2522.8 bps/笔   ← 占 9%
────────────────────────────────────
              298 笔   -46.1 bps/笔
```

一个 +200bps 的账本被止损本身打成 -46bps。典型案例:AIA 那笔止损在 -25.2%,持满是 **+27.7%**。

正确做法:`stoploss` 设成逐仓爆仓线让它不参与决策,在 `custom_exit` 里按观察价判定。
按观察价的止损档位扫描(hold 235m,净 bps):

| 止损 | train | holdout | 最差单笔 |
|---|---|---|---|
| -10% | +74.1 | +193.6 | -18.9% |
| -15% | +61.7 | +222.1 | -29.7% |
| -25% | +52.4 | +274.7 | -31.8% |
| 无 | +53.8 | +283.9 | **-99.2%** |

无止损时最差单笔是爆仓(1x 逐仓做空,持仓内翻倍即归零)。实测中 5 笔这样的轧空
吃掉了 1522 笔正常单赚的全部利润。-6% 这一档会砍掉赢家(中位数转负),不要更紧。

### 6.2 「同 pair 只能持一笔」会静默吃掉赚钱的信号

Freqtrade 一个 pair 同时只能有一笔仓位。持续极端资金费的一轮里会连续结算多次
(该宇宙里有 59 个 pair 是 1h 结算),235 分钟的持仓把后续全吞掉:

```
全部事件 n=2207  mean=+61.7bps
去重后   n=1625  mean=+11.4bps    ← 被吞掉的正是赚钱的那批
```

这不是 `max_open_trades` 的问题——cap 6 / cap 12 / 无上限的结果完全一样。
**任何按事件入场、持仓长于事件间隔的策略都要先做这个检查**:
把事件级的收益分布和「组合层面实际能吃到的那些」分开算,两者差多少。
§2.1 的 streak 条件同时也是这个问题的解:把入场推到一轮的中后段,吃到的就是赚钱的那批。

### 6.3 事件研究用算术收益,不要用对数收益

做空端的凸性会被对数收益系统性高估。同一批事件:对数 +219bps,算术 +136bps。
差异全在尾部,而这类策略的盈亏正是尾部决定的。

### 6.4 futures 回测必须先确认 funding/mark 的 timeframe 与本版本一致

freqtrade 2026.1 的 `funding_fee_timeframe` 与 `mark_ohlcv_timeframe` 都是 **1h**
(`freqtrade/exchange/exchange.py:157-158`),不是文档里常见的 8h。手工构造的 `-8h-` 文件
**不会报错,只是永远不被读到**,所有交易的 `funding_fees` 静默为 0——本项目因此把七个季度
的结果高估了 110 个百分点,直到把 `-1h-` 文件补上才发现。

强制检查:futures 回测跑完先看导出里 `funding_fees` 是否全为 0。若全为 0,
必须能说清是"持仓从不跨结算"还是"数据没被读到",不能默认前者。
日志里的 `No history for X, mark, 1h found` 就是征兆,它不是警告而是错误。

资金费按 funding 与 mark 在 `date` 上的 **inner join** 逐行累加
(`exchange.py:3930`),所以两个文件必须在同一时间网格上,且 funding 要保留交易所真实的
结算戳(本宇宙内 1h / 4h / 8h 共存,重采样成统一周期会改变信号本身的数值)。

## 8. 陷阱清单

- 引擎 `stoploss` 在 1m 冷门 pair 上会被插针扫掉,而被扫的单子往往是赢家。见 §6.1。
- 结算周期不是统一 8h;`_minutes_to_next_settlement` 这类硬编码在这个宇宙里是错的。
  重建 funding 数据时按桶求和,并把持仓压到最短结算周期以下。
- 资金费 parquet 的时间戳是结算时刻 T,而事件研究里的入场时刻是 T+1min。
  两者混用会让所有按结算时刻做的关联(如 streak)全部错位并静默返回 NaN。
- 1x 逐仓做空的下限是爆仓不是 -100%:实测最差单笔在无止损时到过 -133%(未截断的算术收益),
  Freqtrade 会先爆仓。永远要有一个观察价止损。
- 多进程回测时两个 22GB 的进程会把 62GB 的机器压进 swap,回测时间从 7 分钟变成 2 小时以上;
  更糟的情况是被 OOM 静默杀掉、日志停在主循环开始处而没有任何报错。
  并发跑 fold 时先按单 fold 的实际 RSS 估算批大小。
- 用 `pgrep -f <pattern>` 等待回测结束时,pattern 会匹配到等待循环自己的命令行,
  导致永远等不到;把命令写进脚本文件再等,或按 PID 等。
- Freqtrade 的 `--export-filename` 在这个版本不生效,导出文件按时间戳命名;
  并发跑同一秒完成的两个 fold 会互相覆盖。用唯一的策略类名区分导出结果。
- 配置文件里的 `datadir` 键不生效,必须用 `--datadir` 命令行参数。
- futures 回测的 funding/mark timeframe 与本版本不一致时不会报错,只是静默不计资金费。
  见 §6.4——本项目因此把结果高估了 110 个百分点。
- 把宇宙扩到全交易所时会混进股票挂钩永续(NVDA / GOOGL / META / MSTR / COIN 等)和极新的币,
  freqtrade 没有它们的杠杆档位,会直接报错拒绝回测整个白名单。先量化这些 pair 的贡献
  (本例只占 4.1% 的事件、单笔 +5.9bps)再决定是剔除还是补数据。
- 从 parquet 读回的日频序列会丢掉时区,而 K 线的 `date` 是 tz-aware UTC,
  `Series.map` 会静默返回全 NaN。做流动性/资金费这类外部序列映射时必须先对齐时区并断言命中率。
- 248 个 pair 的季度回测单进程约占 12GB;14 个同时跑会被 OOM 杀掉一部分,
  日志停在「Backtesting with data from ...」而无任何报错。批大小按单进程实测 RSS 定。

## 10. Dry-run 运行手册

生产件:

| 文件 | 作用 |
|---|---|
| `user_data/strategies/FundingSkewMomentum5m.py` | 策略。资金费走 DataProvider,回测与实盘同一路径 |
| `config-funding-skew-dryrun.json` | dry-run 配置。动态 pairlist,100 USDT,6 仓位,复利。仓库 `.gitignore` 忽略 `config*.json`,完整副本见同目录 `dryrun-config.example.json` |
| `scripts/build_niche_dailyvol.py` | 流动性表。**每天必须刷新** |
| `user_data/niche_work/daily_qv.parquet` | 上者产出。策略读它做 `min_qv` 判定 |

### 10.1 两层筛选(都是动态的)

第一层 pairlist 只决定"盯哪些",不是"交易哪些"。≥1000 万的门槛每天通过约 186 个 pair
(区间 121-246),但每月真正开仓的只有中位 14 个。

```json
"pairlists": [
    {"method": "VolumePairList", "number_assets": 300, "sort_key": "quoteVolume",
     "lookback_days": 30, "lookback_timeframe": "1d",
     "min_value": 150000000, "refresh_period": 86400},
    {"method": "AgeFilter", "min_days_listed": 10}
]
```

- `VolumePairList` 的 lookback 模式对区间内成交额**求和**(`VolumePairList.py:289`),
  与策略用的"日成交额中位数"口径不同,所以 `min_value` 只能当粗筛:
  1.5 亿 = 30 天总和,相当于日均 500 万,**故意低于**策略自己的 1000 万门槛,
  保证粗筛不会砍掉策略本会接的单子。精确判定在 `min_qv` 参数里。
- `min_days_listed: 10` 对齐 `build_niche_dailyvol.py` 的 `VOL_MIN_DAYS`。
- **不要**把"历史上触发过事件的那 190 个 pair"做成静态白名单:那是拿结果筛样本,
  其中 32% 只触发过 1-2 次,且新上市的 pair 是收益来源之一。
- 黑名单:杠杆代币 `.*(UP|DOWN|BULL|BEAR)/.*`,加 26 个股票挂钩永续
  (NVDA / GOOGL / META / MSTR / COIN 等)——freqtrade 没有它们的杠杆档位,
  留在白名单里会直接拒绝启动整个回测/实盘。

### 10.2 每日刷新(不做的话新 pair 永远进不来)

```bash
freqtrade download-data -c config-funding-skew-dryrun.json \
  --datadir user_data/data/niche_funding --timeframes 5m 1d --days 40
python3 scripts/build_niche_dailyvol.py --datadir user_data/data/niche_funding/futures
```

流动性窗口是 30 天中位数,慢变量,每天刷一次足够。它之所以不放进策略内计算:
30 天窗口在 5m 上需要 8640 根启动 K 线,freqtrade 拒绝超过交易所单次供给量 5 倍的
`startup_candle_count`,实盘启动也拉不到那么多。资金费这个快变量则相反,必须实时,
所以走 DataProvider。

### 10.3 仓位与本金

`dry_run_wallet: 100` + `stake_amount: "unlimited"` + `max_open_trades: 6`,
即每笔用 当前钱包/6,约 18 USDT,远高于币安 USDⓈ-M 的 5 USDT 最小名义额,实测无订单被拒。
`unlimited` 是复利:赚了之后下一笔仓位变大,好坏季度都会被放大。

`max_open_trades` 基本不是约束——真正绑住手脚的是"同 pair 只能持一笔":
cap 4 / 6 / 20 分别成交 1530 / 1536 / 1538 笔,单笔均值都是 +89bps。
所以 cap 是**杠杆选择**而非信号选择,按能承受的回撤定即可,不要当参数调。

### 10.4 启动

```bash
freqtrade trade -c config-funding-skew-dryrun.json \
  --datadir user_data/data/niche_funding --strategy FundingSkewMomentum5m
```

启动后先确认三件事,任何一件不对就停下来查,不要让它空跑两周:

1. 日志里 pairlist 解析出的 pair 数在 120-250 之间。太少说明 `min_value` 设错了。
2. 随便挑一个 pair,确认 `dp.get_pair_dataframe(pair, candle_type="funding_rate")` 非空。
   为空则整个策略不会开任何仓,而且**不会报错**。
3. `daily_qv.parquet` 的最新日期是昨天。过期意味着新 pair 永远进不来。

### 10.5 观察期与判定(主 SKILL.md §2.6)

至少 2 周。按事件密度,期望约 4 笔/天(90 分位 15 笔),2 周约 50-60 笔——
样本量只够看成交质量,**不够判定收益**,不要用两周的 PnL 下结论。

要对的账:

- **markout**:每笔成交后 1s / 5s / 30s / 5min 的价格相对成交价的偏移。
  入场用市价单,实盘 markout 显著差于回测隐含值 = 成交假设太乐观,
  回到主 SKILL.md §2.1 加码成本重跑,而不是调策略参数。
- **实际价差**:回测注入的是 5bp 半价差。记录每笔成交时的盘口价差,
  若中位数超过 10bp,§5.8 的数字要按 §4 的成本敏感性表往下修。
- **资金费对账**:dry-run 用估算(`_fetch_and_calculate_funding_fees`),实盘用交易所实际
  账单。对比每笔的 `funding_fees` 与交易所 income 记录,差异说明 1h 网格数据有缺口。
- **事件触发数**:与 §5.8 的季度笔数折算后的日频量级对得上吗?
  明显偏少通常是 pairlist 或 `daily_qv` 过期,不是行情。

### 10.6 dry-run 期间不要做的事

- 不要调 `hold_minutes` / `close_stop` / `fr_threshold`。§5.2 已实测:
  在这个策略上按窗口重选参数比固定参数更差。
- 不要因为某个 pair 连续亏就拉黑它。收益是正偏的,剔除每季最好的 10% 笔后归零(§5.7),
  按单 pair 短期表现裁剪等于砍掉尾部。
- 不要开多头。50 笔样本、4/7 个 fold 为正、单 fold -65.5 到 +50.8 USDT,没有证据(§5.3)。
