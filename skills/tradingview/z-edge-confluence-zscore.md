## 2. 整体策略思路总结

### 2.1 核心指标

三个因子各自做 Z-Score（同一 `zscore_period = 100` 窗口，`(x - sma) / stdev`，`stdev = 0` 时取 0）：

| 因子 | 定义 | 权重 |
| --- | --- | ---: |
| `zPrice` | `roc = (close - close[14]) / close[14] * 100` 的 Z-Score | 0.4 |
| `zRsi` | `ta.rsi(close, 14)` 的 Z-Score | 0.3 |
| `zVol` | `volume / ta.sma(volume, 20)` 的 Z-Score | 0.3 |

`composite = (zPrice*0.4 + zRsi*0.3 + zVol*0.3) / (0.4+0.3+0.3)`（权重和为 0 时分母取 1）。

自适应平滑：

```
atrPctRank = ta.percentrank(ta.atr(14), 100)                    // 0~100
dynLenFloat = 15 - (15 - 2) * (atrPctRank / 100)                // 高波动 -> 短，低波动 -> 长
dynLen  = max(round(dynLenFloat), 1)
alpha   = 2 / (dynLen + 1)
smoothComposite = na(prev) ? composite : prev + alpha * (composite - prev)   // 变 alpha 的递归 EMA
```

即：ATR 百分位越高（波动越大），平滑窗口越短、反应越快；关闭自适应时固定用 `smoothing_base = 5`。

### 2.2 市场假设

把「动量 + RSI + 成交量」三条截然不同量纲的序列各自标准化到同一个 Z 空间再加权，
得到一条合成强度线；用这条线的**穿越零轴**判断多空状态转换。默认模式不是均值回归，
而是趋势跟随（`Zero Cross`）；`Threshold Reversion` 模式才是在 ±1.5 极值处反向进场。

### 2.3 入场 / 出场（原策略完整规则）

```
longEntry  = allow_longs  and (mode=="Zero Cross" ? crossover(smooth, 0)  : crossover(smooth, -1.5))
shortEntry = allow_shorts and (mode=="Zero Cross" ? crossunder(smooth, 0) : crossunder(smooth, +1.5))
longExit   = crossunder(smooth, exit_level_long  = 0.0)
shortExit  = crossover (smooth, exit_level_short = 0.0)

riskAmount   = account_equity(10000 固定输入) * 1%
stopDistance = ATR(14) * 2.0
size         = min(riskAmount / stopDistance, account_equity * 100% / close)

if longEntry  and size>0 : entry Long ;  if use_stop_loss : exit stop = close - stopDistance
if shortEntry and size>0 : entry Short;  if use_stop_loss : exit stop = close + stopDistance
if longExit  and position>0 : close Long
if shortExit and position<0 : close Short
```

`process_orders_on_close = true`，即 Pine 在信号 K 线的收盘价成交。

### 2.5 源码中值得单独指出的六点

1. **默认参数下出场信号与反向入场信号完全同条件。** `exit_level_long = exit_level_short = 0`，
   于是 `longExit == shortEntry`、`shortExit == longEntry`。默认行为是零轴翻转反手、永远在市，
   与同作者的 TrendShift 结构一致（见 [trendshift-supertrend-adx-regime.md](trendshift-supertrend-adx-regime.md)）。
   只有把 `exit_level_*` 调离 0，出场才成为独立规则。
2. **成交量因子没有方向。** `zVol` 是 `volume / SMA(volume)` 的 Z-Score，恒为「量大则正」，
   与价格涨跌无关。它占 30% 权重，因此任何放量（无论涨跌）都把 composite 往多头方向推。
   这是作者的设计后果而非语法错误，忠实移植中原样保留，但它会系统性地制造上穿零轴。
3. **背离检测算了但没接单。** `bullDiv` / `bearDiv` 只进 `plotshape`，不参与任何下单条件；
   `pctRank`、`absZ`、`strengthLabel`、信息表同理。移植时不得把背离写进交易逻辑。
4. **ATR 止损是默认开启的真实风控**（`use_stop_loss = true`），且是入场时一次性挂出的固定价止损，
   不随后续 K 线移动。这一点与 TrendShift 不同：本策略的作者默认配置**含**止损，
   因此纯信号版必然与作者默认行为不同，结论中不可混淆。
5. **仓位不复利也不看真实权益。** `account_equity` 是一个静态输入（默认 10000），
   不是 `strategy.equity`，所以「每笔风险 1%」始终按 10000 计算；`max_pct_equity = 100`
   在止损很窄时才会生效。本阶段整体改为矩阵统一固定名义仓位。
6. **`process_orders_on_close = true` 与 Freqtrade 的成交时点不同。** Pine 用信号 K 线收盘价成交，
   本项目口径是收盘确认、**下一根开盘**成交。这是引擎差异，必须披露，不试图靠调参对齐收益。

另有两处数值健壮性问题，移植时按 pandas/numpy 语义处理并记录：`roc` 在 `close[14] = 0` 时除零；
`volRatio` 在 `SMA(volume) = 0`（连续零成交量）时除零。原 Pine 会产生 `na`/`inf`，
移植实现应显式置为无信号，而不是让脏值进入 Z-Score 窗口。

### 2.6 本阶段纯信号实验的保留 / 移除（依据 `SKILL.md` §5）

| 原规则 | 本阶段 |
| --- | --- |
| 三因子 Z-Score 合成 composite | **保留** |
| ATR 百分位自适应 EMA 平滑 | **保留** |
| `Zero Cross` 零轴上穿做多 / 下穿做空 | **保留**（默认模式） |
| 零轴反向穿越平仓 | **保留**（唯一出场，等价于反手） |
| 背离检测 | 不接单（原本就不接单，非本阶段移除） |
| ATR 2× 固定止损 `use_stop_loss` | **移除**（这是作者默认开启的风控，属本阶段口径差异） |
| `risk 1% / ATR` 仓位与 `max_pct_equity` 上限 | **移除**，改为矩阵统一固定名义仓位 |
| `Threshold Reversion` 模式（±1.5） | 本轮不测；如需测另立版本 |

因此本策略的纯信号版**与作者默认配置存在实质差异**（少了 ATR 止损）。
若纯信号版亏损，不能直接断言作者的完整策略也亏损；需要另立一个忠实全策略版本单独回测。

### 3.2 移植差异与实现说明

- **总体标准差**：Pine `ta.stdev` 除以 n，pandas `rolling.std()` 默认除以 n-1；实现显式 `ddof=0`。
- **`ta.percentrank` 口径**：统计**前 n 根**中 <= 当前值的比例，窗口不含当前根。
- **变 alpha 的 EMA**：`dynLen` 逐 K 变化，只能逐根递归，不能用 `ewm(span=...)`。
  `na` 传播按源码复刻：composite 或 alpha 为 `na` 时平滑值为 `na`，下一根从 composite 重新起算。
- **除零加固**：`roc` 在 `close[14] <= 0`、`volRatio` 在 `SMA(volume) <= 0` 时置为无信号，
  避免 `inf` 污染后续 100 根 Z-Score 窗口。原 Pine 会把脏值带进窗口，这是修正而非复制错误。
- **`math.round`**：Pine 是四舍五入（远离零），numpy `round` 是银行家舍入；实现用 `floor(x+0.5)`。
- **成交时点**：Pine `process_orders_on_close = true`（信号 K 线收盘成交），
  本项目口径是收盘确认、**下一根开盘**成交。引擎差异，不做对齐调参。
- **反手成交**：Pine 用一张反向 `strategy.entry` 换向，Freqtrade 需要"平仓 + 反向开仓"两笔，
  两笔都收费。矩阵统计 `same_candle_flips` 报告同根换向的实际发生次数。
- **出场绑定**：出场信号 = 源码的 `exit_level` 穿越 **或** 对侧入场（后者复刻 Pine 的反手即平仓）。
  出场原因分别标记为 `exit_level` 与 `reversal`，在审计里可分开计数。
- **`ZEdgeFull` 的止损锚定**：Freqtrade `custom_stoploss` 的返回值是相对**当前价**的比例，
  直接返回常数会把固定止损变成移动止损；实现改用 `stoploss_from_absolute` 把止损锚在入场价上。
- **未实现项**：背离检测（源码中不参与下单）、信息表与绘图，全部不移植。

### 3.3 引擎残留保护（SKILL.md §5 要求披露）

- `minimal_roi = {}`：真正无 ROI 出场。
- `stoploss = -0.99`：Freqtrade 必填字段，无法移除；逐单元统计 `stop_loss` 与 `liquidation` 笔数。
- `trailing_stop=False`、`use_custom_stoploss=False`、`position_adjustment_enable=False`、无 protections。
- 杠杆固定 1 倍，隔离保证金，爆仓由引擎模拟并单独统计。

### 4.4 结果读法

1. **两个版本的毛利都几乎正好是零，净亏损几乎全部等于手续费。**

   信号本身没有可扣费的毛边际，这不是"成本略高"的问题。
2. **净利为正的单元 v1 只有 4/24、v2 只有 3/24**，且全部由 1~2 个币撑起：
   - v1 majors 1d：12 个币有交易，LAB 用 2 笔贡献 +38.4，而整单元净利 +22.2（占 173%）。
   - v1 high_vol 1h：EVAA +102.7、US +70.3，整单元 +82.7；20 币中只有 6 个为正。
   - v1 mixed 1d：SYN **单笔** +37.0，整单元 +16.6。

   - v2 majors 15m（唯一 PF>1 的单元，1.19）：BEAT 一个币 +48.6，整单元 +37.3，20 币中 10 个为正 ——

3. **全样本逐币**：v1 只有 4/59 个币在 6 个周期合计后为正，v2 只有 6/59。
4. **成本随周期单调放大**（每单元手续费占 1000 USDT 起始资金的比例）：
   v1 1d 0.2% → 1h 7% → 5m 62% → **1m 91%**；v2 1d 0.01% → 1h 1% → 5m 12% → **1m 55%**。

5. **v2 的换手确实低得多**（29,621 笔 vs 80,373 笔），亏损也小得多（-2,870 vs -7,749），

### 4.8 止损实现的一处修正（必须披露）

第一轮止损矩阵（同样是 24+24 单元）**已作废重跑**，原因是移植实现的缺陷，不是策略本身：

- 症状：majors 1h 出现 21 笔标记为 `trailing_stop_loss` 且盈利高达 +60% 的空单出场
  （例：LAB 空单 14.434 → 5.758）。固定止损不可能在空头浮盈 60% 时成交。
- 原因：freqtrade 的 `stoploss_from_absolute()` 最后一行是
  `max(min(stoploss, 1.0), 0.0) * leverage`。空头浮盈超过约 50% 时，
  真实止损相对当前价的比例大于 1，被这个 `min(..., 1.0)` 截断，
  于是引擎把止损价重设为 `当前价 × 2`，**固定止损被悄悄变成了移动止损**。
- 修正：不再使用该辅助函数，直接按 `stop_rate / current_rate` 计算相对比例（不截断），
  使止损绝对价格在整笔交易中恒定。修正后 majors 1h 从 -74.6 变为 -53.2，
  `trailing_stop_loss` 标签只剩 19 笔且全部为小额亏损（该标签只表示"初始止损被替换过"，
  不表示止损在移动）。
- 附带核实：LAB 在 2026-07-06~07-12 从 16.4 连续跌到 0.43（成交量同步放大），
  是真实行情不是坏数据，因此那笔空单的浮盈本身是真的，问题只在出场价。
- 本文档 §4.6 的所有数字来自修正后的重跑；作废的第一轮结果不予采用。

## 5. 最终是否采用的结论

**结论日期**：2026-09-05（研究已结束，不再追加实验）

### 5.1 移植正确性：**验收通过**

- 源码取自 pine-facade 快照（MD5 `aa793f19f2981298ab058327afa92c46`），逐行对照实现。
- 三项验证全部通过：与 Pine 字面直译实现的公式对拍最大差 3.2e-14（percentrank 与自适应 EMA 为 0）；
  6 个截断点 × 7 列的前缀因果性 0 处不一致；真实 freqtrade 回调下无同根多空冲突。
- `lookahead-analysis`（2080 笔）：no bias detected。
- 出场原因分布证实没有隐含 ROI / 止损 / 超时出场。

### 5.2 策略信号：**不采用**

依据（v1/v2 为纯信号，v3/v4 为加回作者 ATR 止损后的版本）：

1. 96 个月内矩阵单元（4 版本 × 24）中净利为正的只有 15 个，其中绝大多数由 1~2 个币
   甚至单笔撑起。四个版本的 2026-07 净利：-7,749 / -2,870 / -7,963 / -3,409。
2. **四个版本的毛利都约等于零**（+166 / +118 / +197 / +168），净亏损几乎完整等于手续费。
   信号在扣费前就没有边际，不是被成本压掉的边际。
3. **加止损不解决问题**：逐格 A/B 下，止损只在 6/24（Zero Cross）和 5/24（Reversion）
   个单元里改善结果，合计分别是 -214.0 和 -539.3。截短尾部亏损的同时也截断了顺势段。
4. **1d 上"交易少、成本低"这条路已被 8 个月的数据否掉**：手续费降到资金的 1.25% 以下，
   但四个版本的 1d 八个月毛利分别是 -229.6 / -157.4 / -152.4 / -246.3，全部为负；
   正负单元 15/32、13/32、13/32、10/32，接近抛硬币。
5. 逐币看，2026-07 的 59 个币里只有 4 个（v1）/ 6 个（v2）合计为正。
6. 降低换手不能救：v2 的交易数只有 v1 的 37%，亏损降到 37%，方向不变。
7. v2/v4 的多空 35/65 不对称，与源码里"无方向的成交量因子占 30% 权重"的结构缺陷一致；
   这是设计层面的问题，不是参数问题。

### 5.4 适用范围与限制

- 本结论仅覆盖：Binance USDT 永续、2026-07 单月、上述冻结币池、1d~1m 六个周期、

### 5.5 否决依据存档（避免重复探索）

多因子 Z-Score 合成 + 零轴穿越（或对称阈值回归）这一族信号，在加密永续上于 2026-07 的
四类币池、六个周期、两种入场模式下均未通过纯信号成本检验，且毛利本身就约等于零。
再次遇到同类脚本（把若干量纲不同的指标标准化后加权，用合成线穿越固定水平线开仓）时，
先算「毛利 / 手续费」这一比值，不必重跑完整矩阵；
另外要专门检查合成因子里是否混入了**无方向的量能项**，它会系统性地制造单边信号。

两条已经用数据关掉的补救路线，不要重试：
**加 ATR 止损**（4.6：两个版本、48 个 A/B 格，净负贡献）与
**退到 1d 靠低换手省成本**（4.7：8 个月、128 个单元，手续费降到 1.25% 以下但毛利仍为负）。
