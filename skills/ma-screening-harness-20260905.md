# 均线筛选（Harness）策略：实现与走向前验证

## 来源和范围

原文：知乎《均线筛选量化策略：一次 Harness Engineer 思想的量化实践》
https://zhuanlan.zhihu.com/p/2032120164750205868 （2026-04-27 发表）。
文章给出三层框架的完整描述与评分公式，但只贴了 JavaScript 片段，
没有给出参数网格、回测周期、K 线周期和若干阈值。

本目录下的实现是独立的 Python 走向前回测，不复刻原文任何收益曲线
（原文也未给出收益数字）。

## 原文规则（逐条照抄）

第一层 标的池：全市场 USDT 永续按美元成交量降序取前 150。

第二层 双层赛马：
- 第一层竞争（参数）：每个币跑多组 (fast, slow) 均线组合，各自独立回测，
  取综合评分最高的一组作为该币的代表分数与专属参数。
- 第二层竞争（币种）：所有币按代表分数排序，取前 N 进入白名单。

综合评分（原文原样）：

    score = min(winRate * 100, 100)              * 0.30
          + min(profitFactor * 20, 60)           * 0.30
          + max(0, 1 - maxDrawdown / maxMDD)*100 * 0.20
          + volPct * volPctBonus            // volPctBonus 默认 10

第三层 执行与风控：
- 金叉做多、死叉做空的反手系统（`crossUp` / `crossDown`）。
- 动态移动止盈：浮盈 ≥7% 回撤 3% 离场，≥4% 回撤 2%，否则 1.5%。
- 市场状态：BTC 波动率分位高时降低仓位系数（volatile 0.5 / high_vol 0.8 /
  low_vol 0.7），极端行情禁止做空。
- 整个筛选流程周期性滚动重跑。

## 执行口径

- 数据：`user_data/data/binance_public/panels/<tf>`，2025-01-01 至 2026-08-16，
  860 个 Binance USDT 永续，含真实资金费率与可交易掩码。
- 走向前：每个再平衡点只用截止当日的数据打分，选出的白名单与参数在随后
  完全未被触碰的 7 天上交易，共 72 个再平衡点（1h、90 天窗口）。
- 成交：K 线收盘出信号，下一根 K 线承担收益；反手系统换向按两倍名义计费。
- 成本：默认单边 0.05%，另测单边 0.10%；资金费按 `rate × 小时数 / 8` 逐根计提。
- 杠杆 1，白名单内等权，每个再平衡点重新等权。
- 移动止盈只用收盘价判断，不假设盘中成交。

## 对照组

选币和选参数各自是否有用，靠对照组区分：

1. 同一池内随机抽 10 个币（用它们各自被选中的参数）——衡量选币层。
2. 同一排名的最后 10 名——衡量排序方向。
3. 白名单的 10 个币改用随机参数——衡量选参数层。
4. 白名单的 10 个币改用固定 50/200——衡量"参数赛马"相对"直接用慢均线"。
5. 全池 150 个币；以及同期 BTC 买入持有。

## 结论

1. **选币层没有可验证的信息量。** 评分与随后 7 天收益的 rank IC 为 +0.011
   （t = 0.81，53% 的再平衡点为正）。加上第三层风控后，白名单落在同池随机
   抽签分布的第 57 百分位——即与随机选币不可区分。
2. **选参数层有作用，但作用是"少交易"。** 白名单换随机参数会从 +4.2% 掉到
   −50.7%；而被选中的参数高度集中在 50/200、40/200、50/150 这类慢组合
   （入选者中位数 10 笔信号，全池中位数 23 笔）。也就是说赛马赢的不是
   "更好的趋势判断"，而是"更低的换手成本"。直接固定 50/200 就能拿到大部分
   这个好处。
3. **评分公式里唯一有方向性的成分是回撤项。** 分项 rank IC：回撤（取负号）
   +0.037（t = 2.96），胜率 +0.011，盈亏比 −0.010。胜率和盈亏比在样本外
   基本无效，而它们占了权重的 0.60。
4. **第三层风控是整套东西里唯一稳健的部分。** 移动止盈把最大回撤从 60% 压到
   24%，再叠加市场状态仓位压到 11%，代价是收益同样被削。它对白名单和对随机
   选币同样有效，说明它与筛选层无关。
5. **整体不能上实盘。** 最好的一组（1h + 全部三层）总收益 +9.7%、
   Sharpe 0.46、t = 0.54，且换任意一个旋钮（成本、白名单规模、窗口长度、
   周期）符号就翻转。这是典型的噪声。
6. 样本期 BTC 为 −23.9%，属于震荡偏空环境。原文假设的"妖币趋势延续"
   在这段样本里没有出现，结论不能外推到单边牛市。

原文自己已经指出双层赛马"参数层过拟合叠加币种层过拟合"。本次验证的补充是：
**币种层不但过拟合，而且样本外完全无效；参数层的效果可以被一条固定慢均线复制。**

## 复现

```bash
# 走向前（纯信号）
python3 scripts/ma_harness/walkforward.py --tf 1h --workers 24 \
    --out user_data/research/ma_harness/v_base.json
# 走向前（含第三层风控）
python3 scripts/ma_harness/walkforward.py --tf 1h --workers 24 \
    --trail --market-state --out user_data/research/ma_harness/v_full.json
# 评分与对照组
python3 scripts/ma_harness/report.py --wf user_data/research/ma_harness/v_base.json
# 引擎交叉验证（向量化 vs 逐笔事件循环）
python3 scripts/ma_harness/verify_engine.py
```

`verify_engine.py` 用一份独立写的逐笔账户循环复算同一条腿，最坏相对偏差
3.4e-4（来源是费用与资金费的加法/乘法计提差异），确认结论不是引擎错误。
最初版本有两个已修复的错误，重跑任何变体前需留意：穿叉方向曾取到旧的
符号（等于反向交易），移动止盈曾用当根收盘价决定当根仓位（前视）。

## 追加：选币能力与波段捕获能力的拆分（2026-09-05）

问题：是选不中妖币，还是选中了但信号拿不住行情。两者用同一批再平衡日分开测。

脚本：`scripts/ma_harness/spike_analysis.py`（因子对未来波动/波段/趋势干净度的
rank IC）与 `scripts/ma_harness/wave_capture.py`（同一批币上换不同信号规则）。

### 选中妖币到底值多少

同样的规则，按决策时波动率分三档（每档同样的 68 个日期）：

| 决策时波动率档 | 中位最大波段 | Donchian 平均 | Donchian t | 均线 50/200 平均 |
| --- | --- | --- | --- | --- |
| 前 30（妖币） | 55.3% | +3.94% | +1.43 | +1.69% |

### 对"如何精准选妖币并吃到主升浪"的直接回答

1. 命中"会动的币"不难，已实现波动率就够（IC 0.64），无需复杂评分。原文的评分
   反而是反向的。
2. 命中之后仍然赚不到，因为没有任何决策时信息能预测这一波是趋势还是震荡；
   一半以上的妖币窗口是震荡。
3. 均线穿叉在趋势窗口只拿到 17.5% 的可用波段，在震荡窗口每次亏 20%；
   Donchian 突破在趋势窗口能拿到 81%，是"拿住波段"这一项上明显更好的规则。
4. 即便换成 Donchian，整体仍是尾部游戏（5% 的窗口贡献全部盈利，t 1.43），
   这决定了任何"精准选妖币"的方案都必须承受长期负中位数、靠少数大波段回本。

## 再追加：选币窗口 3 天 vs 7 天（2026-09-06）
